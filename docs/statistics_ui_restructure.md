# STAT-UI-RESTRUCTURE-01 — «Обзор» и «Покупки»

Изменён только общий presentation двух подразделов. DTO, агрегаторы, fingerprint,
кеш/INDEXED и остальные подразделы не меняются. Навигация и ZIP из двух файлов сохранены.
Аналитические данные не помещаются в раскрывающиеся панели.

## Порядок

| Подраздел | Раньше | Теперь |
|---|---|---|
| Обзор | Общие KPI → CustomerScope → профили → товарная активность → узкий и расширенный портрет покупателей | CustomerScope → демография профилей → активность товарного среза → расширенный портрет подтверждённых покупателей |
| Покупки | Товарный срез → STRICT → общая частота/интервалы → сравнение политик → совместные категории | STRICT → частота с графиком → интервалы → первая/последняя покупка периода → категории → товарный срез → видимое сравнение политик |

## Доказанные повторы

- Повторная плитка «Профили текущего среза» убрана из Обзора: то же поле customers остаётся
  в общей шапке. База профильной демографии обозначена контекстной подписью.
- Плитка «Покупатели» товарного среза убрана из Обзора: то же purchase_users остаётся
  в строке «Клиенты с покупками» таблицы активности и в существующем разделе Заказов.
- Пол/возраст покупателей убираются только после точного сравнения каждой строки
  (label, buyers, buyer_rate) со срезом расширенной таблицы. Сохраняются неизвестные группы.
  При старом DTO, недоступной расширенной аналитике или несовпадении значений
  узкая таблица остаётся; данные не реконструируются и не исправляются.
- Обе таблицы пар объединены из одного массива saved.pairs. Ключи category1/category2
  используются прямо для получения подписей, сопоставления по названиям нет.
  Семь колонок сохраняют прежние абсолютные и обе условные частоты; TOP-10 не применяется.
  Неопределённые категории и предупреждения сохранены.

## Контексты

Под заголовком однородной группы находится постоянно видимая вторичная подпись:
клиентская база, профили, товарный срез или подтверждённые покупки всех товаров.
Даты CustomerScope и покупателей читаются из их собственных сохранённых period;
даты товарного среза — из analysis_filter. Отсутствующие периоды не заменяются
предположением по сегодняшним настройкам. Неполное покрытие/источники обозначаются явно.

Правило товарной статистики не объявляется STRICT или EXTENDED: используемые при
расчёте статусы могут отличаться от аналитических F/sold и F/sold/CP.
Первые/последние покупки покупателей относятся к выбранному периоду, а не
историческому поиску когорт. Сравнение политик, валюты и все его строки остаются открыты.

## Общий рендеринг

ReportBlock text с признаком context используется Qt/HTML/XLSX как одна модель.
Qt и HTML придают подписи вторичный стиль; XLSX сохраняет её отдельной обычной строкой.
Порядок данных един для трёх форматов. Графики частоты и сравнения стоят непосредственно
перед своими таблицами. Существующие предупреждения о категориях/неполноте не удалены.

copurchase_sections(..., combined=True) применяется только новым отображением Покупок.
Значение по умолчанию сохраняет прежний контракт вспомогательной функции;
Денежные показатели, RFM, Когорты не получают изменений.
