# Единый ZIP-экспорт рекомендаций

На вкладке результатов кнопка «Экспорт рекомендаций» предлагает пробу на первых
50 подтверждённых клиентах BPR-MF либо полный экспорт этой аудитории. Полная
выгрузка запускается только явным выбором пользователя. Имя назначения —
`Recommendations.zip`. Замена существующего архива требует отдельного согласия.

## Контракт файлов

Архив содержит ровно три файла:

* `RecommendationsOnlineStore.csv`: `CustomerID;ProductID`, UTF-8 BOM.
  CustomerID — подтверждённый, не invalid телефон в прежнем формате из цифр;
  российские 10 цифр и префикс 8 нормализуются в 7. ProductID содержит до десяти
  различных актуальных кодов через запятую, в порядке итогового hybrid Top-10.
  Покупатели без пригодного телефона и все совпадения телефона внутри выбранной
  аудитории исключаются только из этого CSV.
* `RecommendationsMindbox.csv`: строго
  `CustomerMindboxId;Quantity;ProductGroupOffline1C;CustomFieldKoefficient`.
  Canonical ID, Quantity=1, актуальный код, готовый `HybridItem.final_score`
  с двумя десятичными знаками и запятой. Телефон не требуется.
* `RecommendationsAnalytics.xlsx`: сводка фактической выгрузки, покупатели,
  проверенные исходные BPR-рекомендации, итоговые hybrid-рекомендации с реальными
  компонентами расчёта, товарные агрегаты, методология и версии источников.
  Подробные листы автоматически делятся при достижении лимита Excel.

Все файлы получают данные из одного потока `ExportCustomer`. Идентификаторы и
контакты записываются в Excel как буквальный текст, включая ведущие нули и строки,
похожие на формулы. Оценки, остатки и вероятности остаются числами. Отсутствующий
propensity не заменяется нулём. Near-zero с соответствующим предупреждением
показывается научной записью доли, чтобы очень малая вероятность не выглядела
достоверным нулём. Прогноз имеет исторический статус RESEARCH_ONLY, срез
01.09.2026 и горизонт [01.09.2026, 01.10.2026).

## Расчёт и согласованность

`RecommendationBatchSession` один раз подготавливает модель, канонический
identity resolver, каталог и разрешение товарных кодов. Численное ранжирование
наследуется от `RawBprInferenceService` без изменения dtype, оценки или порядка
равных значений. `HybridRecommendationService` и существующий purchase consensus
применяются без изменения формул и бизнес-правил. Обрабатывается вся индексированная
история заказов клиента. История GUI не читается страницами для этого расчёта.

Подготовленные пустые purchase scopes копируют только изменяемое состояние.
Соединения SQLite доступны только для чтения, транзакции ограничены пакетами по
100 клиентов. Длительная блокировка canonical storage не удерживается. До и после
пакета и непосредственно перед публикацией сверяются версии identity, профилей,
истории, модели, каталога, правил и доступных propensity-артефактов/ключа.
Изменение источников отменяет весь неопубликованный архив.

Propensity использует существующие проверки model/dataset/source/identity/key_id
и готовый prediction lookup. Секрет и HMAC не включаются ни в строки экспорта,
ни в диагностические сообщения. Отсутствие совместимого propensity не мешает
выгрузке рекомендаций. Полная проверка целостности реального индекса истории
и пересчёт prediction artifacts не выполняются.

## Жизненный цикл и ресурсы

GUI запускает отдельный `QProcess`; поиск покупателя и его отмена независимы.
Канал JSON содержит только этапы, счётчики и статические категории ошибок.
Ручная отмена передаётся через stdin, без terminate/kill. В Windows численные
библиотеки импортируются до запуска блокирующего читателя stdin; ранняя отмена
ожидает в канале и затем обрабатывается. Закрытие окна ожидает штатной очистки.
Прямой `QApplication.quit()` также ожидает завершения отменённого процесса.

Запись openpyxl потоковая. Телефоны для выявления коллизий размещаются в небольшой
служебной SQLite внутри закрытого временного каталога; товарные агрегаты ограничены
размером каталога. Промежуточный XML, CSV, XLSX и ZIP принадлежат текущему запуску.
На Windows каталог получает ограниченные ACL до записи персональных данных.
Завершённый ZIP сохраняет эти ограничения при атомарном перемещении.

Проверяются свободное место (резерв 20 ГиБ плюс начальная оценка staging), private
commit процесса (3 ГиБ), доступная физическая память (4 ГиБ) и системный commit
(3 ГиБ). Проверки кооперативные, не являются жёстким резервированием ОС.
Отмена/контроль ресурсов работают также при сжатии Excel и проверке CRC.
Архив публикуется только после проверки всех трёх файлов и CRC ZIP/XLSX.
Ошибки не запускают повторную попытку автоматически.

Численный расчёт остаётся последовательным и может занимать несколько часов для
полной аудитории. Нельзя обещать время по небольшой выборке: покупатели с большим
числом заказов и нагрузка на диск могут существенно увеличить длительность.
Checkpoint/resume не предусмотрен. Обновление источников потребует новой явной
попытки. Недостающие/повреждённые профили пропускаются с агрегированным счётчиком.
