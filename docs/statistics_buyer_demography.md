# Покупательская аналитика по демографии

Новые показатели рассчитываются внутри BuyerAggregates по подтверждённым покупкам STRICT_COMPLETED. Политики, факты покупок, CustomerMerges, выбор первого снимка и область покупательского периода сохраняются. Товарный отбор не ограничивает покупательскую аналитику.

## Источник и методика

Используются уже накопленные покупательские состояния и тот же доступный профиль, который формирует существующий портрет покупателей. Возраст определяется calendar_age на buyer_statistics.as_of, а не на дату исторического заказа. Пол: Мужчины / Женщины / Не указан; восемь возрастных групп берутся из customer_demographics. Покупатели без профиля включены в неизвестные группы и отдельно остаются в missing_profiles существующего портрета.

Для каждой группировки покупатели, заказы, один/повторные покупатели и неизвестные денежные оценки согласуются с общими STRICT-показателями. Пол и возраст — независимые группировки, их итоги не складываются.

Денежные показатели относятся к известной сумме принятых товарных позиций priceOfLine. Доставка не включается, повторного умножения на quantity и пересчёта валют нет. Средний и медианный чек включают только достоверно оценённые заказы своей валюты, в том числе достоверный нулевой заказ. Неизвестная сумма не становится нулём. При нулевом основании средний/медиана и доли недоступны.

Колонка «Заказы без достоверной денежной оценки (все валюты)» является общим счётчиком группы. Она повторяется как справочная в RUB/KZT и не распределяет UNKNOWN_CURRENCY, MIXED_CURRENCY или INVALID_PRICE по валютам.

## Точная медиана и память

Суммы заказов интернируются как Decimal, а покупательское состояние хранит только четырёхбайтовые коды достоверных STRICT-сумм. Исходные идентификаторы и индивидуальные факты в новый DTO не входят. Повторного чтения Orders/Customers и SQL-запросов по покупателям нет.

После связывания профилей пол и возраст обрабатываются последовательно. Числовой рабочий буфер одной группировки освобождается до построения другой. Для повторяющихся сумм используется существующая точная гистограммная медиана, для высокой уникальности — ограниченная сортировка кодов по Decimal. Медиана вычисляется по отдельным заказам, а не по оборотам покупателей.

Новый компонент консервативно учитывает интернирование, массивы и временную память медиан. Бюджет по умолчанию — 256 MiB добавочного состояния/рабочей памяти; это не лимит RSS всего процесса. При превышении расчёт прерывается MemoryError, приближённая медиана не подставляется. Проверки отмены выполняются при обходе покупателей/кодов и подготовке медиан. Временная база и файлы истории не создаются.

## DTO и совместимость

Внутри buyer_statistics.policies.STRICT_COMPLETED добавлен необязательный ключ demographic_analytics:

- gender: три агрегированные строки;
- age: восемь агрегированных строк.

Каждая строка содержит label, buyers, buyer_rate, orders, mean_orders, single_buyers, repeat_buyers, repeat_rate, unvalued_orders и money. Для RUB/KZT в money содержатся known_buyers, known_orders, amount, mean_order, median_order, amount_rate. Денежные значения остаются Decimal-строками, доли — конечными процентами либо None.

Валидатор проверяет точные ключи, порядок групп, счётчики, знаменатели, недоступность значений и сверку с глобальными итогами. При недоступных Customers новый ключ равен None. Отсутствие ключа в старом результате означает «Нет данных в сохраненном результате. Пересчитайте статистику для получения новых показателей».

Схема сохраняемого контейнера остаётся 10: расширение необязательное и старые результаты читаются без миграции. Calculation fingerprint изменяется, новый модуль включён в аттестацию зависимостей. Старый последний результат не удаляется и автоматически не пересчитывается. Существующий INDEXED не меняется; при несовпадении provenance требуется его отдельное штатное обновление.

## Представление

В «Клиенты → Обзор» после существующего портрета идут две таблицы активности по полу/возрасту. В «Денежные показатели» после прежних RUB/KZT добавлен раздел с четырьмя таблицами: пол RUB, пол KZT, возраст RUB, возраст KZT.

Все шесть таблиц поступают из grouped_buyer_sections в общий presentation-контракт GUI/XLSX/HTML. Новых KPI-карточек, вкладок и графиков нет. Архив сохраняет ровно Статистика.xlsx и Статистика.html.
