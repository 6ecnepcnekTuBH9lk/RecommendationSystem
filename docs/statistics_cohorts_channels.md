# Каналы первой и второй наблюдаемой покупки

STAT-BUSINESS-03A дополняет только STRICT_COMPLETED в когортной аналитике.
Вся доступная история до прежнего отсечения определяет два первых уникальных
заказа. Фильтр месяцев когорт применяется до формирования новых агрегатов.
CustomerMerges и первая подходящая версия заказа остаются прежними.

## Источник и компактное состояние

REFERENCE передаёт firstAction.channel.ids.externalId и firstAction.channel.name
из уже прочитанного заказа в необязательные параметры CohortAggregates.add.
PurchaseOrderFact, RFM и BuyerAggregates не расширены; дополнительных чтений
Orders/Customers нет. На покупателя добавлены только first_channel/second_channel,
которые заменяются одновременно с прежними первым и вторым ключами заказа.

INDEXED уже сохранял канал в orders.details. Теперь канал сохраняется до проверки
не связанных с ним необязательных агрегатных полей. Технически отсутствующая
проекция канала вызывает ошибку, а не превращается в группу «Не указан».

Синтетическая проверка выявила старое расхождение: при равном UTC-времени
внутренние SID не сохраняют лексикографический порядок исходных ID заказов.
Новый индекс schema 3 сохраняет целочисленный cohort_order_rank, построенный
по общей нормализованной строке ID, и передаёт его в когортный ключ.
Это воспроизводит порядок REFERENCE; исходные order ID не публикуются в индексе
или DTO. SID фактов/дедупликации не меняются. Ранг строится до удаления исходной
временной таблицы ID; рабочая таблица рангов находится в приватной SQLite на
выбранном диске и удаляется до публикации. Действуют прежние SQL progress,
ресурсные guards, отмена и атомарная публикация.

Формулы и правила когорт/B02 не изменены. При одинаковом времени новый INDEXED
может исправить ранее неверный выбор первого/второго заказа и связанные с этим
первые/повторные суммы, приводя их к REFERENCE. Сохранённые результаты не меняются.
Старый реальный индекс в этой задаче не перестраивается.

## Группировка и знаменатели

Идентификатор канала — единственный ключ группы, без справочной классификации
маркетинга, города или онлайн/офлайн. Общий адаптер приводит числовые ID к строке,
сохраняя ведущие нули строк. Одинаковые названия не объединяют разные ID;
переименование при прежнем ID не создаёт переход. При нескольких названиях
отображается лексикографически минимальное непустое имя среди выбранных первых
двух заказов покупателей отображаемых когорт. Совпадающие имена уточняются ID.

Нет ID — группа «Не указан», даже если имя есть. Нет только имени при известном
ID — идентификатор остаётся известным. Любая пара с отсутствующим ID, включая
«Не указан → Не указан», относится к неопределённому переходу.

- Доля первых покупок: все покупатели отображаемых когорт.
- Доля вторых и доля пары: покупатели с наблюдаемой второй покупкой.
- Доля от повторных первого канала: повторные покупатели, начавшие в этом канале.
- Достоверное сохранение: тот же известный ID / (тот же + другой известные ID).
- Нет знаменателя — None, а не ноль процентов.
- Переходы используют наблюдаемые события, без ограничения базой горизонтов eligible.

Каждая первая/вторая покупка учитывается ровно один раз. Все пары выводятся без
TOP-ограничения: количество по убыванию, затем ID первой и второй покупки.
«Не указан» присутствует в распределениях, в том числе с нулём покупателей.

## DTO и представление

Необязательный блок:
cohort_statistics.policies.STRICT_COMPLETED.purchase_channels:
buyers, repeat_buyers, same_known_buyers, other_known_buyers,
unknown_transition_buyers, same_known_rate, channels[], transitions[].

Каталог channels содержит только external_id/name, first_buyers/first_rate,
second_buyers/second_rate. Пары содержат first_external_id/second_external_id,
buyers, repeat_rate, first_channel_repeat_rate. Customer ID, order ID и
индивидуальные последовательности отсутствуют. Закрытая валидация проверяет
типы, уникальность, порядок, все знаменатели и маргинальные суммы пар, а также
размер отображаемой когортной совокупности и прежний observed_repeat_buyers.

Контейнер кеша — schema 10. Отсутствующий блок поддерживается: сообщение о новом
расчёте без автоматического пересчёта при открытии или экспорте. Новый helper и
изменённый контракт источника входят в algorithm fingerprint. Индекс schema 2
не совместим с новым расчётом; потребуется штатное построение schema 3 отдельно.

После прежних когортных таблиц добавлены один общий блок KPI и три таблицы.
Общий presentation-слой задаёт идентичный порядок/данные GUI, XLSX и HTML.
Новых вкладок/графиков нет. ZIP содержит только «Статистика.xlsx» и «Статистика.html».
