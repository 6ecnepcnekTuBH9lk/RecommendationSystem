# STAT-UI-RESTRUCTURE-02 — денежные показатели покупателей

Изменён только общий presentation подраздела «Клиенты → Денежные показатели».
Расчётные данные и остальные страницы/подразделы сохраняются.

## Структура до/после

Раньше: KPI RUB + полнота/квинтили/годы RUB → KPI KZT + полнота/квинтили/годы KZT →
общая методика демографии → пол RUB → пол KZT → возраст RUB → возраст KZT.

Теперь:

1. Постоянный контекст подтверждённых покупок всех товаров, фактический сохранённый период
   и раздельность валют; краткое различие известной суммы и полной оценки.
2. Денежные показатели — RUB: шесть KPI → полнота оценки → график квинтилей и полная
   таблица → годы с покрытием → пол → возраст.
3. Денежные показатели — KZT: тот же порядок, одновременно с RUB.
4. Общие показатели без оценки по полу и возрасту — одна видимая таблица всех валют.

Аналитика не скрывается: нет переключателей валют, сворачивания и отдельных окон.
Графики прежние, их ровно два, каждый непосредственно перед своей таблицей квинтилей.
Существующие ограничения денег/доставки/покрытия перенесены целиком в общую методологию один раз.

## Проверка дублирования по полям

| Представление | Источник | Решение |
|---|---|---|
| Шесть KPI валюты | strict.money[currency].amount, mean_order, median_order, mean_complete_per_buyer, median_complete_per_buyer, repeat_amount_rate | Все сохранены |
| Полнота оценки: десять строк | known_orders, known_buyers, mean_known_per_buyer, median_known_per_buyer, complete_buyers, complete_amount, complete_repeat_buyers, complete_repeat_rate, complete_repeat_amount, complete_repeat_amount_rate | Все сохранены: это другие поля, даже когда числа совпали |
| Неоценённые заказы демографической группы | strict.demographic_analytics[dimension][i].unvalued_orders | Валюта не входит в путь поля. Две прежние копии RUB/KZT заменены одним общим счётчиком |
| Остальные демографические деньги/счётчики | group.money[currency].* | Сохранены раздельно: валюта входит в источник |
| STRICT-колонка сравнения политик в Покупках | Те же strict.money.*, но отдельная цель сравнения с EXTENDED | Не удаляется и не меняется; основная денежная аналитика также остаётся |

Численный дубль не определяется совпадением в одном наборе данных.
Перед удалением невалютной колонки presentation проверяет соответствие обеих исходных
проекций исходному полю каждой группы. Если подтверждение отсутствует, колонки остаются.
Пол и возраст — две группировки одной базы; строки общей таблицы не складываются между ними.
Все неизвестные группы сохранены. Неизвестные и смешанные валюты не распределяются между RUB/KZT.

Сходство названий «средний известный подытог» и «средняя полная сумма» не означает дубль.
Не объединяются доля повторных в известной сумме и доля повторных в полном обороте.
Известный подытог сохраняется при недоступной полной оценке; None не заменяется нулём.

## Совместимость

grouped_buyer_sections сохраняет прежний контракт. Преобразование выполняет один общий
ReportBlock-слой для GUI/HTML/XLSX. Незнакомая структура вспомогательных секций отображается
без потери исходного содержимого. Старые DTO без демографической аналитики показывают
прежние заглушки; общие счётчики не выдумываются.

Квинтили, границы, число покупателей, суммы и повторность сохранены. Годовые строки,
покрытие и признак полного/неполного года сохранены. Decimal не пересчитываются и не
переводятся в float в новой проекции; оформление использует прежние денежные ячейки.

Аудит A05/R04 отмечал повторение денег в сравнении политик. В этой задаче сравнение
остаётся открытым в Покупках, и никакие его данные не удаляются. Предложение старого
аудита о скрытой детализации не применяется.

Агрегаторы, DTO, fingerprint, схема кеша и INDEXED schema 3 не изменяются.
Mindbox не пересчитывается, индекс не перестраивается. Обзор, Покупки, RFM и Когорты
не реструктурируются. ZIP сохраняет только Статистика.xlsx и Статистика.html.
