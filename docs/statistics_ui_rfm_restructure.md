# STAT-UI-RESTRUCTURE-03

Изменено только общее представление подраздела «Клиенты → RFM-анализ».
`rfm_sections()` сохраняет прежний контракт; новый `rfm_report_sections()`
переставляет его готовые таблицы для GUI, HTML и XLSX. Вычислений по источникам нет.

## Последовательность

1. Дата отсечения, база 48 месяцев, контекст из сохранённых границ окна.
2. Активность и качество наблюдения: три самостоятельно названные таблицы.
3. Сегменты: прежний график с шестью вариантами, расширенный бизнес-портрет.
4. Единая открытая справка: сегмент, прежнее определение, прежнее действие.
5. Отдельные таблицы баллов и эмпирических порогов.
6. Готовое сравнение последовательных последних/предыдущих 12 месяцев.
7. Готовое сравнение действующих политик.

## Удаление дублей и совместимость

B149 опускается только при наличии B150 во всех шести срезах и **точном**
совпадении упорядоченных троек `(segment, buyers, buyer_rate)` каждого среза.
Окно и валюта определяются одинаковым путём к сохранённому срезу.
B150 не пересчитывается. Все его 42 строки и 12 колонок сохранены.
При несовпадении вызывается существующий `statistics_cache.validate_result()`:
недопустимое противоречие отклоняется прежним `StatisticsCacheError`.
Если контракт допускает малое расхождение долей, обе таблицы остаются открытыми.
Частично присутствующий расширенный блок отклоняется действующим валидатором.

Для старого DTO без `segment_business` показывается B149, без пустой B150.
Сохраняется пояснение о недоступности расширенных данных; автоматического
пересчёта нет. При отсутствии всей RFM остаются прежнее сообщение о доступности,
график с прежним состоянием и справочник. Нули не подменяют отсутствующие данные.

Прежняя двухколоночная справка действий заменена единой трёхколоночной таблицей.
Сохранены определения `SEGMENT_LABELS`, действия `RFM_BUSINESS_ACTIONS` и семь
сегментов, включая смысл недоступной оценки UNSCORABLE. Сегменты не означают
гарантированно новых или потерянных клиентов.

## Численная сохранность

Все исходные таблицы B145–147, B150, B154–159 передаются без изменения строк,
колонок, порядка, Decimal, None и точности. Определения из B149 вынесены в справку.
Общие B149/B150 поля проверяются перед удалением дубля. RUB/KZT не складываются;
известный подытог остаётся доступным при отсутствии полной M. Число таблиц RFM
снижается с 12 до 11; для результата без RFM — с трёх до двух (удалена пустая B150).
Состояние с допустимым неточным совпадением сохраняет 12 таблиц.

Контекст и ограничения видны постоянно. Переключатели меняют только график,
аналитических аккордеонов нет. Другие подразделы не меняются. Двухфайловый ZIP,
форматирование, схема DTO, fingerprint, расчётные правила, RFM-ядро и INDEXED
сохранены. Проверки используют исключительно синтетические данные.

Проверки: новый `tests/test_statistics_rfm_ui_restructure.py`, существующие
RFM GUI/HTML/XLSX/ZIP2 и проверки общей геометрии/представления. Дополнительно
сравниваются замороженное представление до задачи и новое, снимки двух тем
при ширине 1000/1600 и состояние cache/INDEXED до/после.
